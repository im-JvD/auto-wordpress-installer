# استقرار خودکار و ایزوله وردپرس در داکر (WordPress & Docker Stack)

یک اسکریپت خودکار، امن و کاملاً ایزوله به زبان Bash جهت راه‌اندازی و مدیریت وردپرس روی سرورهای مجازی لینوکس (VPS) با استفاده از **Docker**، **Nginx**، **PHP-FPM** و **Certbot (Let's Encrypt SSL)**.

این پروژه با **اصول سخت‌گیرانه عدم تداخل و امنیت بالا** مهندسی شده است:
- **عدم تداخل پورت دیتابیس:** کانتینر دیتابیس در شبکه داخلی و ایزوله داکر اجرا می‌شود. پورت `3306` **هرگز روی سرور هاست باز (Expose) نمی‌شود**؛ بنابراین هر دیتابیس دیگری که از قبل روی سرور شما فعال باشد کاملاً امن و دست‌نخورده باقی می‌ماند.
- **اسکن ایمن و فقط-خواندنی پورت‌ها (Read-Only Check):** پورت‌های `80` و `443` قبل از استقرار بررسی می‌شوند. اگر سرویسی (مانند پنل‌های سرور یا پروکسی) این پورت‌ها را اشغال کرده باشد، اسکریپت هیچ پروسه‌ای را Kill نکرده و با نمایش پیام راهنما، امکان استفاده از پورت‌های جایگزین کلودفلر (مثل `8443`) را فراهم می‌کند.
- **حذف و مدیریت کاملاً ایزوله:** عملیات‌های آپدیت، مشاهده لاگ و حذف (Uninstall) صرفاً و منحصراً بر روی کانتینرها، ولوم‌ها و شبکه‌های همین پروژه اعمال می‌شود و هیچ تغییری در سایر کانتینرها یا سرویس‌های سرور ایجاد نخواهد کرد.
- **پشتیبانی ویژه از Duplicator و Backupino:** دارای حالت اختصاصی برای بازگردانی سایت‌های بکاپ‌گیری شده، بدون نیاز به نصب اولیه و خام وردپرس.

```text
                      [ Host Ports 80 & 443 / 8443 ]
                                     │
                                     ▼
                         ┌───────────────────────┐
                         │   Nginx Reverse Proxy │ (HTTP/2, SSL, Security Headers)
                         └───────────┬───────────┘
                                     │
                     ┌───────────────┴───────────────┐
                     │                               │
                     ▼                               ▼
           ┌───────────────────┐           ┌───────────────────┐
           │   Certbot (ACME)  │           │ WordPress PHP-FPM │
           │ (Auto-renew loop) │           │ (wordpress:fpm)   │
           └───────────────────┘           └─────────┬─────────┘
                                                     │
                                                     │ Internal Bridge Network
                                                     ▼ (Port 3306 - Not Bound to Host)
                                           ┌───────────────────┐
                                           │ MariaDB / MySQL   │
                                           │ (wp_db container) │
                                           └───────────────────┘
```

## نصب سریع با دستور تک‌خطی (Quick Start)

کافیست دستور زیر را کپی کرده و در ترمینال سرور مجازی خود (اوبونتو، دبیان، سنت‌او‌اس و...) اجرا کنید:

```bash
git clone https://github.com/im-JvD/auto-wordpress-installer.git /opt/wp-docker && cd /opt/wp-docker && chmod +x setup.sh scripts/*.sh && sudo ./setup.sh
```

---

### دسترسی سریع با دستور اختصاصی `wordpress`

پس از اولین اجرای اسکریپت، یک دستور سیستمی سراسری به نام `wordpress` در سرور شما ثبت می‌شود. از آن پس، در هر مسیری از سرور که باشید تنها با تایپ کلمه زیر منوی مدیریت برای شما باز می‌شود:

```bash
wordpress
```

## ساختار منوی اصلی (Categorized Main Menu)

برای سهولت در کاربری و جلوگیری از شلوغی، گزینه‌های اسکریپت در ۵ دسته اصلی سازماندهی شده‌اند:

```text
====================================================================
           WordPress & Docker Stack Manager (Isolated)
====================================================================
 [1] Deployment & Restoration (Fresh WP / Duplicator Restore)
 [2] Database Management (Create, Delete, View Info, phpMyAdmin)
 [3] Service Operations (Start, Stop, Restart, Status, Logs)
 [4] Maintenance & Updates (Update Images, Self-Update Script)
 [5] Complete Uninstall (Safe Purge Stack Only)
 [0] Exit
====================================================================
```

---

### [1] استقرار و بازگردانی (Deployment & Restoration)
* **Deploy Fresh WordPress:** راه‌اندازی صفر تا صد وردپرس خام با Nginx، PHP-FPM، دیتابیس ایزوله، سرتیفیکیت SSL و شبکه اختصاصی.
* **Deploy Stack for Migration / Restore:** آماده‌سازی تمام زیرساخت‌ها با مقادیر بهینه‌شده برای فایل‌های حجیم و پوشه وب آماده برای ریستور توسط Duplicator یا Backupino.

### [2] مدیریت پیشرفته دیتابیس‌ها (Database Management)
یک زیرمنوی جامع برای مدیریت کامل پایگاه‌های داده درون داکر:
* **مشاهده مشخصات و لیست دیتابیس‌ها:** نمایش هاست (`db`)، یوزر، رمز عبور اصلی و روت، به همراه فهرست تمامی دیتابیس‌های فعال.
* **ایجاد دیتابیس و کاربر جدید:** ساخت آسان دیتابیس‌های اضافی با دسترسی‌های تفکیک‌شده.
* **حذف ایمن دیتابیس:** امکان حذف دیتابیس‌های غیرضروری با تاییدیه دو مرحله‌ای (با محافظت سخت‌گیرانه از دیتابیس‌های سیستمی).
* **اجرای phpMyAdmin تحت وب:** راه‌اندازی یک کلیک و در صورت نیاز (On-Demand) پنل گرافیکی phpMyAdmin روی پورت دلخواه (پیش‌فرض ۸۰۸۰).
* **توقف phpMyAdmin:** غیرفعال‌سازی و بستن آنی phpMyAdmin جهت حفظ کامل امنیت و آزادسازی حافظه رم سرور.

### [3] عملیات و پایش سرویس‌ها (Service Operations)
* **Start / Restart Services:** اجرای مجدد یا ری‌استارت تمام کانتینرهای استک (Nginx / OpenLiteSpeed, WordPress, Database, Certbot).
* **Stop Services:** متوقف کردن امن تمام کانتینرها بدون حذف دیتابیس یا فایل‌ها (آزادسازی فوری پورت‌ها و منابع پردازنده و رم).
* **Service Status & Stats:** مشاهده وضعیت سلامت کانتینرها (Healthcheck)، میزان مصرف پردازنده و رم، و تست زنده پاسخ‌دهی سایت.
* **View Service Logs:** مشاهده لاگ‌های اختصاصی وب‌سرور، سرویس PHP، دیتابیس، تمدید خودکار Certbot یا استریم زنده تمامی لاگ‌ها.
* **Auto-Start on Boot (systemd):** فعال‌سازی و ساخت خودکار سرویس سیستمی `wp-docker.service` جهت اجرای خودکار تمام کانتینرهای استک پس از ری‌استارت یا ریبوت سرور مجازی بدون نیاز به دخالت کاربر.

### [4] نگهداری و بروزرسانی‌ها (Maintenance & Updates)
* **Switch / Change Web Server:** جابجایی و تغییر آنی و کاملاً ایمن بین وب‌سرورهای OpenLiteSpeed و Nginx بدون داون‌تایم و با حفظ ۱۰۰٪ فایل‌ها و دیتابیس.
* **Switch / Change PHP Version:** تغییر و سوییچ آنی نسخه PHP به هر کدام از نسخه‌های دلخواه (PHP 7.4, 8.0, 8.1, 8.2, 8.3) با یک کلیک و کامپایل خودکار درایورهای دیتابیس.
* **Update Container Images:** دریافت آخرین نسخه‌های پایدار ایمیج‌های داکر و بازسازی مجدد کانتینرها بدون از دست رفتن اطلاعات.
* **Self-Update Script:** همگام‌سازی و بروزرسانی مستقیم و هوشمند اسکریپت از مخزن رسمی گیت‌هاب با یک کلیک.

### [5] حذف کامل و ایمن (Complete Uninstall)
* حذف با تاییدیه متنی `yes`.
* متوقف کردن و حذف **فقط و فقط** کانتینرها، ولوم‌ها و شبکه مرتبط با این پروژه.
* تضمین عدم دستکاری به سایر سرویس‌ها، دیتابیس‌ها یا کانتینرهای دیگر سرور.

## نحوه بازگردانی بکاپ با Duplicator یا Backupino

1. از منوی اسکریپت گزینه `[1] > [2]` (حالت Migration / Restore) را انتخاب کنید.
2. نسخه PHP دلخواه خود (مثلاً 8.3 یا 8.2 یا 7.4) را انتخاب کنید.
3. پس از پایان عملیات، مشخصات دیتابیس نمایش داده شده را یادداشت کنید:
   * **Database Host:** `db`
   * **Database Name:** *(نام انتخابی شما)*
   * **Database User:** *(کاربر انتخابی شما)*
   * **Database Password:** *(رمز عبور انتخابی شما)*
4. فایل‌های `installer.php` و آرشیو بکاپ (فایل ZIP) را **مستقیماً داخل پوشه میانبر زیر** قرار دهید:
   👉 **`/opt/wp-docker/html`** *(این پوشه توسط اسکریپت به صورت خودکار ایجاد شده و در نرم‌افزارهای WinSCP یا FileZilla مستقیماً در دسترس است)*

   همچنین می‌توانید فایل‌ها را در سرور آپلود کرده و با دستور docker منتقل کنید:
   ```bash
   docker cp installer.php wp_app:/var/www/html/
   docker cp your_archive.zip wp_app:/var/www/html/
   ```

   پس از قرار دادن فایل‌ها، این دستور را در ترمینال بزنید تا مجوزهای دسترسی وردپرس تنظیم شود:
   ```bash
   docker exec -it wp_app chown -R www-data:www-data /var/www/html
   ```
5. آدرس نصاب را در مرورگر باز کنید (مثال: `https://yourdomain.com/installer.php`).
6. مراحل بازگردانی را طی کرده و برای هاست دیتابیس کلمه **`db`** را وارد نمایید.

## راهنمای اتصال با Cloudflare و پورت‌های جایگزین (اختیاری)

اگر پورت ۴۴۳ سرور شما توسط سرویس دیگری (مانند پنل‌های پروکسی/Xray) اشغال شده باشد، اسکریپت به صورت خودکار پورت‌های استاندارد کلودفلر (مانند `2087` یا `8443`) را پیشنهاد می‌دهد. برای اینکه سایت شما بدون نیاز به نوشتن شماره پورت در آدرس مرورگر مستقیماً با `https://yourdomain.com` باز شود، دو مرحله ساده زیر را در Cloudflare انجام دهید:

### ۱. تنظیم وضعیت SSL/TLS روی حالت Full (بسیار مهم)
* در داشبورد Cloudflare وارد دامنه شده و از منوی چپ به بخش **SSL/TLS** بروید.
* حالت رمزگذاری (Encryption Mode) را حتماً روی **Full** یا **Full (strict)** قرار دهید.
> ⚠️ **نکته مهم:** اگر این گزینه روی *Flexible* باشد، کلودفلر ترافیک را به جای HTTPS به صورت HTTP خام به پورت امن سرور ارسال کرده و با خطای `400 Bad Request: The plain HTTP request was sent to HTTPS port` مواجه خواهید شد.

### ۲. پنهان‌سازی پورت با قابلیت Origin Rules
برای اینکه کاربران نیازی به وارد کردن پورت در انتهای آدرس نداشته باشند:
1. در داشبورد کلودفلر از منوی سمت چپ به بخش **Rules** > **Overview** بروید.
2. در بخش قالب‌ها کارت **Change port** (با برچسب Origin Rules) را یافته و روی **Create from template** بزنید.
3. در فرم باز شده:
   * **Rule name:** یک نام دلخواه (مثلاً `WordPress Port Route`) وارد کنید.
   * در بخش **When incoming requests match:**
     * گزینه **Custom filter expression** را انتخاب کنید.
     * فیلد **Hostname** را برابر با نام دامنه یا ساب‌دامین خود (مثلاً `tst.yourdomain.com`) قرار دهید.
   * در بخش **Destination Port:**
     * گزینه **Rewrite to...** را انتخاب کرده و شماره پورت فعال وردپرس خود (مثلاً **`2087`**) را وارد کنید.
4. روی دکمه **Deploy** (یا Save) کلیک کنید.

اکنون کلودفلر ترافیک ورودی استاندارد (پورت ۴۴۳) را در پس‌زمینه به پورت سرور شما هدایت می‌کند و سایت مستقیماً و بدون تداخل باز خواهد شد.

## ساختار فایل‌های پروژه (Directory Structure)

```text
/opt/wp-docker/
├── setup.sh                 # اسکریپت اصلی مدیریت و منوی ترمینال
├── html/                    # پوشه میانبر مستقیم به فایل‌های سایت (مخصوص آپلود در WinSCP/FileZilla)
├── docker-compose.yml       # پیکربندی کانتینرهای داکر (پروفایل‌های OLS و Nginx)
├── .env.example             # نمونه متغیرهای محیطی
├── ols/                     # پیکربندی وب‌سرور پرسرعت OpenLiteSpeed و کش LSCache
│   ├── httpd_config.conf.template
│   └── vhconf.conf.template
├── php/
│   └── custom.ini           # کانفیگ بهینه‌شده PHP جهت آپلود فایل‌های سنگین
├── nginx/
│   ├── nginx.conf           # کانفیگ اصلی Nginx با هدرهای امنیتی
│   └── conf.d/
│       ├── http.conf.template # کانفیگ موقت جهت تاییدیه Let's Encrypt
│       └── ssl.conf.template  # کانفیگ نهایی HTTPS با پشتیبانی از HTTP/2 و OAuth
├── scripts/
│   ├── ssl-init.sh          # اسکریپت صدور دو مرحله‌ای SSL
│   └── db-create.sh         # اسکریپت ایجاد دیتابیس و یوزر جدید
└── certbot/                 # محل نگهداری گواهی‌های SSL
```

## نکات کلیدی امنیت (Security Highlights)

* **ایزولاسیون دیتابیس:** پورت ۳۳۰۶ تنها در شبکه اختصاصی داخلی داکر قابل دسترسی است و ارتباطی با بیرون ندارد.
* **SSL مدرن با تمدید خودکار:** استفاده از پروتکل‌های ایمن TLSv1.2 و TLSv1.3 به همراه لوپ تمدید خودکار دوره‌ای.
* **جلوگیری از اجرای بدافزار:** مسدودسازی مستقیم اجرای کدهای PHP در پوشه `/wp-content/uploads/`.
* **مسدودسازی فایل‌های حساس:** عدم امکان دسترسی خارجی به فایل‌های پنهان مانند `.env` و `.git`.
* **عملیات بدون تخریب:** عدم اجرای هرگونه دستور خطرناک مانند پاک‌سازی فراگیر داکر یا تغییر در فایروال سرور.
